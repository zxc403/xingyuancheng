二 · 黑屏诊断：V5 (52K) 的 5 个根因（按可能性排序）

① 致命：RGBA16F 浮点纹理未检测扩展

V5 的 createTexture() 直接用 gl.RGBA16F + gl.RGBA, gl.FLOAT 创建纹理，没有调用 gl.getExtension('EXT_color_buffer_float')。在 WebGL2 里，把浮点纹理当作 FBO 渲染目标必须先启用这个扩展，否则驱动静默失败，画面就是黑的（不报错）。

// V5 第 446 行
function createTexture(w,h,filter){
  var t=gl.createTexture();gl.bindTexture(gl.TEXTURE_2D,t);
  gl.texImage2D(gl.TEXTURE_2D,0,gl.RGBA16F,w,h,0,gl.RGBA,gl.FLOAT,null);
  // ❌ 没有 gl.getExtension('EXT_color_buffer_float')
  // ❌ 没有 gl.checkFramebufferStatus(gl.FRAMEBUFFER)
}
修复方法：在 getContext('webgl2') 之后立刻 gl.getExtension('EXT_color_buffer_float')，并降级方案：若扩展缺失则用 RGBA8 替代（损失 HDR 但能跑）。

② 致命：FBO 在 w=0 / h=0 时初始化

V5 第 631 行执行顺序：

initGL();           // 第 630 行 → initGLResources()，此时 w=0, h=0
applySize();        // 第 632 行 → 改 w/h, 触发第二次 initGLResources()

第二次 applySize() 里只有 if(cv.width!==nw||cv.height!==nh){...;initGLResources()}，如果浏览器在执行 applySize() 前 cv 已经有 clientWidth（多数情况），那么 nw=nh=正确尺寸，会走 initGLResources 分支重建。但若用户在控制台 resize 或者异步逻辑把 cv 尺寸先变成 0，就会留下 0 尺寸的 FBO，黑屏。

修复方法：在 initGLResources() 里加 if(w<2||h<2) return; 守卫；或者把 init 顺序倒过来（先 applySize 再 initGL）。

③ 严重：TAA 历史纹理初始化为空

V5 第一次 frame() 渲染时，histTex 还没写入任何东西，comp shader 里 texture(uHist, histUv) 采样到的是 未定义值，通常表现为画面整体偏黑（按 blendFactor 0.05 还能透出来一点，但视觉上就是黑屏）。

修复方法：init 时用 gl.clearColor(0,0,0,1); gl.bindFramebuffer(...); gl.clear(...); 把 histTex 清成 0。

④ 中等：RGBA16F 在部分 iOS Safari 上完全不支持

如果在 iPhone Safari / 部分 Android Chrome 上跑，FBO 完整性检查返回 FRAMEBUFFER_UNSUPPORTED，同样会黑屏，且代码没接住。

⑤ 轻微：3 个 program 共享 1 个 VAO，但每帧切换 program 时没 bind VAO

V5 创建 1 个 VAO 给 3 个 program 用，但每次 gl.useProgram(progBloom/progComp) 后没有重新 gl.bindVertexArray(_vao)，某些驱动会丢掉 attribute 指针。表现是第一个 pass (progMain) 正常出图，但 bloom / comp pass 因为 attribute 没绑而不画，最终 composite 输出是空白。

建议：在每个 pass 之前统一 gl.bindVertexArray(_vao);，再 gl.useProgram(...);，最后 gl.drawArrays(...);。

三 · V4 (44K) 的隐患：和 V5 类似但更轻

V4 也用了 3 program + RGBA16F + TAA，但它的 initGLResources 写法略不同（V4 走 3 个 program，没用统一的 init 函数重构），黑屏概率比 V5 低。但它和 V5 共享同样的"无扩展检测 / 无 FBO 完整性校验"问题。所以你 AI 在修 V5 的时候，把 V4 的修法搬过去基本可解决。

四 · 真正能"学到"的技术（在能跑的 3 个版本里）

对星渊城项目最有借鉴价值的是 V3 (34K 完美整合版)——它功能丰富、跑得稳、零外部依赖、单文件 34K 完全可控。V1/V2 是骨架，V3 是肉。

① Gerstner 波 + 浪群包络（最值钱的）

6 个余弦波叠加 + 一个"波群包络"产生"一组浪 → 平静 → 再来一组"的节奏感。

// V3 FSH 第 149-184 行
const vec2 DK[6]=... // 6 个波的方向·波数
const vec2 WA[6]=... // 6 个波的角频率·振幅
float waveGroup(vec2 xz, float t){
  return 0.72 + 0.28*sin(dot(xz,vec2(0.018,0.012))-t*0.25)
                * sin(dot(xz,vec2(-0.009,0.021))+t*0.18);
}
float seaGeo(vec2 xz, float t){
  float g=waveGroup(xz,t);
  float h=0.0;
  for(int i=0;i<6;i++) h+=WA[i].y*g*cos(dot(DK[i],xz)+t*WA[i].x);
  return h;
}

六 · 给你 AI 的"修黑屏"提示词（直接转发）

如果你的 AI 是 Kimi / GPT 之类的，给它这段：

你的 52K 全模块整合版黑屏，根因是 FBO + 浮点纹理初始化失败。三个必修：
1) getContext 之后立刻 gl.getExtension('EXT_color_buffer_float')，失败则降级到 RGBA8。
2) createFramebuffer 后用 gl.checkFramebufferStatus(gl.FRAMEBUFFER) !== gl.FRAMEBUFFER_COMPLETE 校验，不通过直接 fatal() 并打印 status。
3) histTex / mainTex 创建后立刻 gl.bindFramebuffer(...); gl.clearColor(0,0,0,1); gl.clear(gl.COLOR_BUFFER_BIT); 清零，避免 TAA 第一帧采样到未定义值。
4) 每个 program 切换前 gl.bindVertexArray(_vao)。
5) initGL() 和 applySize() 顺序保证 w>0 && h>0 时再创建 FBO。
